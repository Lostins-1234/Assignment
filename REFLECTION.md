Reflections on Usage of AI Agents

## Learning Experience

My experience of working with the AI agents (particular Cursor Agent using Claude) for the Fuel EU Maritime Maritime Compliance platform has been a paradigm-shifting affair. This agent has not only helped me save time, but has also provided crucial feedback in matters of human intervention in the automation process.I learned how to leverage these tools but also understood the importance of human intervention needed while working with these tools.Tools like Cursor are really helpful and time saving for many tasks that needs only implementation but we should always design the approach for any task ourselves which ensures that the code generated by the AI Tool is as per to our use case and also helps keeping it bug free.
We should always review the task whatever we give to the AI Tool and always do any Task by breaking it into small components that allows us to spot errors and bugs and prevent unnecessary complexities introduced by the AI Tools .
We should also be very cautious and as elaborative as we can while giving prompt for any task to AI Tool.

## Efficiency Gains vs Manual Coding

### Time Savings

**Estimated Time Saved: 15-20 hours

The most important efficiency savings derived from:

1. **Project Scaffolding 
- Implemented entire directory structure based on the hexagonal architecture
– Developed all the necessary configuration files (tsconfig.json, package.json, vite.config.js, etc)
- Establish Build Tools and Development Environment
2. **Boiler Plate Code 
- Defining types and interfaces in frontend as well as backend/
- Express Route Handler with error handling
-React components with hooks & state management



## Problems and Restrictions

### Places the Agent Faltered

1. Advanced algorithm structure:
- The pooling algorithm needed several repetitions and hand adjustments
- The original greedy assignment code was broken and had to be human rebalanced.
- The agent produced grammatically accurate but semantically flawed code

2. **Situational Cognizance:**
- Occasionally mixed up the associations between entities (shipId vs routeId)
- Created redundant code that required tidying up
- Overlooked anomalies needing manual inclusion

3. **Expertise in the Sector:**
- Details of Fuel EU Maritime regulation necessitate manual cross-check
- Validation of compliance formulas versus specification required
- Human interpretation required for business rules


## Enhancements for the Future

### 1. Improved Prompt Engineering: Give early prompts more context

Provide instances of the desired patterns.
Clearly define domain relationships and specify edge cases up front.

### 3. Incremental Validation: Test each component as it is created; don't wait until the end to validate; address problems right away; and maintain a functional state throughout

### 4. Documentation as You Go: Record design choices right away; take note of assumptions and trade-offs; update architecture diagrams; and record known limitations.

### 5. Pair Programming Model: Use the agent as a "pair programmer"; review code with both the human and the agent; talk about trade-offs and options; and take advice from the agent.

### 6. Domain Modeling First: Manually construct comprehensive domain models and make relationships and constraints clear.
Validate models prior to implementation; use agents for implementation rather than design.
